## 3. 多子代理编排规则

继承 MASTER-2026-08-03 §5.3 r1–r17 全部规则，增补：

- **r18 契约分阶段解冻**：contracts/ 仅 Phase 0（修订）与 Phase 2 W2-DL（additive path）可写；其余一切相位只读。契约疑义 → 报告回流 leader，禁止就地改契约。
- **r19 测试波纯净性**：Phase 3 全体 agent 只允许新增测试文件；抽 seam 等产品代码改动必须先上报裁决。发现的 bug 记录为 R6-n 交 leader。
- **r20 owned-files 全路径声明**：存在跨模块同名文件（两个 DownloadUploadService、两个 build.gradle 等），prompt 中所有权一律写从仓库根起的完整路径；agent 匹配错误路径视为越权。
- **r21 worktree 钉住**（强化 r11/r12）：leader 预建每路 worktree 并以 working_dir 钉住；agent 不做任何 branch/merge/cherry-pick 操作，只在被钉目录内编辑与 commit。
- **r22 done 证据三件套**：改动文件清单 + 自有门命令完整输出 + 关键行为实测证据（curl 输出/浏览器截图/日志摘录）。缺一视为未完成。
- **r23 相位门分层**：agent 离场前跑自有范围门（表格中列明）；leader 合并后跑全量门再放行下一相位；绿 build ≠ done。
- **r24 commit 纪律**：`feat(web)/fix(app)/fix(web-frontend)/chore(deploy)/test(*)` 中文描述；逻辑单元独立 commit；commit 只含 owned files；测试不红不许 commit；全程禁 push、禁 force。
- **r25 prompt 自包含**：每个子代理 prompt 必须内联：本文件相关 TODO 行原文（含定位与验收）、owned files 全路径清单、自有门命令、r18-r24 规则、done 证据格式；禁止「基于你的研究去修」式委托。
- **r26 并发上限与升级**：单相位 ≤5 路；scope 交叉或需要触碰他人文件 → 立即停手上报 leader 仲裁降级，不得自行扩 scope。
