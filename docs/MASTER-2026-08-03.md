## 0. 红线与协作约定

- **单用户 LAN 架构**：不引入多用户/角色；EH 平台配置仍 Android-local，不进 WebUI
- **设置分区**：可同步用户偏好 → `/settings`（preferences schema）；设备/服务器配置 → `/admin`
- **WebUI 新特性仅 PC/精准定位形态**（鼠标/触控板/手写笔/键盘）：不做移动断点适配；移动端沿用现有 Android 兼容 WebUI，仅回归"不破坏"
- **Android 只测改动面**：未修改的原版功能已知可用，不重复 E2E
- **评审/实现分离**：本模型负责验证、多模态 UI 评审、Markdown 规格；开发模型落地实现
- **configurable-over-hardcoded**：有争议行为做成可配置项（合理默认 + 可切换）
- **neutralize 红线**：不改 `com.hippo.*` 包名/类名；不引入真实画廊域名（`gallery.test`/`showSite*` 态保持）
- **commit 粒度**：每逻辑单元独立 commit，分波提交

## 4. Wave-2 规格：三方模型与冲突策略（已批准方向，细节可就地优化）

### 4.0 产品模型（用户定义，权威）
1. WebUI 与 App 都可单独连远端平台
2. App 进入 WebUI 网络 → 后台自动同步 + **作为 WebUI 客户端行动**
3. 冲突**默认以 App 为准**，高级面板可选

### 4.1 ADR-0003 决策
- **D1 策略可配**：`device_priority`(默认) | `lww` | `web_priority`；序表 `android > web` 置常量。**不为长期离线做保护** → A/C 下同键冲突**无条件**优先级胜，时间戳仅高水位/展示
- **D2 策略设置 App 权威**：随 `syncPolicy` 下发；WebUI 可改但 App push 覆盖，UI 明示
- **D3 客户端模式分档**：Tier-0 独立 / **Tier-1 同步+流式（默认）** / Tier-2 浏览代理 / Tier-3 下载托管；档位 App 可选；Tier-2/3 路由复用 `MOCK_EH_BASE_URL` 拦截器模式
- **D4 网络感知自动同步**：网络回调 + probe 已配对 baseUrl 分片；`autoSyncIntervalSec` 默认 900（0=仅网络变化）；新网络不自动配对；mDNS 后续可选

### 4.2 选项级详设（§1.5 框架）
**行为矩阵**（开发/测试基线）：
| 分歧场景 | A device_priority | B lww | C web_priority |
|---|---|---|---|
| 同键同时编辑 | App 胜 | 新者胜 | Web 胜 |
| App 删 / Web 保留 | **删除传播** | 保留（删端下轮被复活） | 保留 |
| Web 删 / App 保留 | 保留 | 保留 | **删除传播** |
| 各删不同键·tombstone 实体 | 双向传播 | 双向传播 | 双向传播 |
| 各删不同键·soft 实体 | 双向传播 | **不传播** | 双向传播 |
| 不相交新增 | union | union | union |

> **P0 细化（契约 v2 §3.8）**：A/C soft 实体「双向传播」精确化为——优先端删除无条件传播；非优先端删除在优先端持有该键时不传播（同键优先权优先）、优先端不持有时传播；tombstone 实体（history/bookmark）任何策略下双向传播。B 同 v1（soft 不传播、tombstone 传播）。

**粒度**：Level-1 全局单选项本波；Level-2 按实体组覆盖预留 schema 不做；Level-3 逐条仲裁永不做
**切换语义**：即时生效于后续 merge，**不追溯**重合并（B→A 后需在权威端重做删除；进 tooltip）
**兼容**：旧 App×新服务器收敛于 App 视图 ✓；新 App×旧服务器降级不报错 ✓；B=完整回退兜底 ✓

### 4.3 契约修订（sync-conflict-rules v1.0→v2.0）
§1.2 tie-break 参数化；§3.1/§3.3 union 状态位按策略（A/C 删除可传播）；§3.2/§3.4 A/C 无条件优先（time/page 仅同平台回退）；§4 删除表注策略依赖；§5.1 仲裁总序=策略序→实体专属→收到顺序(仅 B)；新增 §8 syncPolicy（`PUT|GET /api/v1/sync/policy`，pull 附 policy；`sync-schemas.json` 增 `SyncPolicy{conflictStrategy,clientTier,autoSyncIntervalSec}`）

### 4.4 实现要点与分波
server：merge 加 strategy 参 + 单测矩阵（策略×实体×分歧）+ policy 端点；app：同规则 merge、自动同步调度、高级面板（策略/档位/间隔）、Tier 路由；web：`/admin·高级·同步策略` Select + D2 提示
分波 **2a 契约+ADR 冻结 → 2b server → 2c app(Tier1/2) → 2d Tier-3（可押后）**
验收：两策略下真机跑 ①App 删/Web 保留 ②同键同时编辑 ③各删不同 ④网络切换自动同步 ⑤Tier-2 走服务器（access log 佐证）
